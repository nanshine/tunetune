# Prepare a bounded resource scope

Keep preparation facts in the resource inventory and reference their IDs from proposal approaches. Check data and annotations, software environment, hardware and storage, model weights, source code/tools, API services and credentials. These are prompts for investigation, not mandatory entries or a closed type list.

For each needed resource state its purpose, trusted source, version or revision, what already exists and what must be prepared. Give estimated download and disk use including cache/extraction, destination and environment isolation where relevant. Mark unknown quantities; do not invent precise memory, cost or transfer estimates. API plans identify the data sent, provider, cost ceiling and behavior when the ceiling cannot be safely enforced. A provider credential is not permission to spend without a limit.

A proposal decision covers only the listed resources and execution boundary. After it is covered, perform the preparation and a real availability check without asking at each package or skill transition. Use the acquisition helper for supported fixed sources and safe destinations; use standard package managers inside an isolated environment for dependencies. Review untrusted repository code before executing it. New sources, private uploads or costs outside scope need a changed decision.

Keep credentials in secure application settings or environment variables; records contain only variable names and nonsecret descriptions. Never ask the person to paste a key into conversation, put secrets into command arguments or snapshot credential files. Existence observations and completed downloads do not prove correct versions, usable interfaces, licensing or scientific suitability.
