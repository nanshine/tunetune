# Improve through informative experiments

Load [research-workspace](../research-workspace/SKILL.md), the current proposal, relevant resources and a calibrated evaluation. Use shared records and tools for mechanics. Establish an operational budget, permitted resources and stopping conditions; count preparation, failures and retests and reserve final-validation time. Continue across rounds within authorization without repeated approvals.

Establish the unchanged system or cheapest credible end-to-end baseline and retain a usable incumbent. Do not stop there merely because it runs. Consider the recommended improvement and a strong quality reference from the proposal; revisit the [technical map](../research-workspace/references/technical-map.md) if exploration is narrow. Training, data, retrieval, inference and distillation are possible interventions. A fixed-rule baseline does not fulfill an explicit training request.

For each affordable round, identify the question, hypothesis, expected observation and meaningful comparator. Choose the experiment with useful information or improvement potential, rather than always increasing complexity or making tiny changes to the same method. Explain why a stronger route or quality reference is run, deferred or ruled out by evidence or boundaries.

Freeze necessary code and configuration and pin the actual inputs. Run through the configured runner, retain process facts and logs, and verify the resulting local or API object before success. An API object identifies the provider, request configuration and calling code, not immutable remote weights; read the record guide for its contract. Keep credentials out of arguments, snapshots and logs. Resource authorization includes only the specified data transfers and cost ceilings.

Evaluate each candidate under a fresh experiment-local attempt with fixed object and evaluation references. Preserve real outputs, diagnostics and available cost, latency and usage. Retries use new IDs; evaluating an unchanged object does not require training again. Compare only compatible measurement and inference conditions, never a mixed ranking.

Interpret actual differences, failures and cost in the experiment analysis. Preserve the incumbent when evidence is inconclusive. Continue, diagnose with [explore](../explore/SKILL.md), or stop according to the remaining budget. Keep the current proposal accurate when findings change its recommendation; update interpretation conditionally while preserving measurements.

Finish by verifying local loading, dependencies and the intended inference interface on real inputs. Select only verified local experiment IDs for delivery; API references remain visible research results, not private local deliverables. Models remain experiment-local and export is separate when requested. Report achieved behavior, evidence, uncertainty, actual consumption and stopping reason. Continue authorized work or offer a concrete next decision, rather than a bare unfinished-status report.
