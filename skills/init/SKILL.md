# 建立或更新研究目标

## 输入与依赖

读取 [research-workspace](../research-workspace/SKILL.md)，执行其接手与授权检查。输入为用户请求、明确项目目录；只有首次安装或补缺时需要用户提供并从可信渠道核验的固定版本本地 kit（本版 0.3.0）。修订已存在目标不要求重新安装 kit。

## 操作

1. 整理使用情境、具体例子、期望结果与来源；调查用户允许查看的现有数据和环境。已有信息直接保留，只问会影响研究方向的缺口，不设长问卷或编造资源。
2. 首次建立/补缺时检查同名文件与工程布局，再使用可信 kit 自带安装器：
   ```sh
   python3 /absolute/local/workspace-kit-0.3.0/install-workspace.py --kit /absolute/local/workspace-kit-0.3.0 --project /absolute/research/project --name '研究名称'
   ```
   替换为真实路径；没有可信 kit 时说明阻塞，不猜下载地址、不从源码拼装、不运行未知脚本。SHA-256 清单只能验证完整性，不能认证发布者。
3. 安装仅补缺失项，不覆盖工程、名称、展示配置或已有 AGENTS；同名内容冲突停止。本版不支持面板升级，不手工覆盖绕过校验。已有指令缺少研究入口时向用户说明差异，经明确同意后合并，不替换既有指令。
4. 按 [文件契约](../research-workspace/references/records.md) 写 goal/resources；例子使用稳定 ID，资源记录实际检查时间和限制。通过基础文件工具保留旧目标后递增 revision，未知内容标待补充。需要集中回答时新增绑定目标哈希的 request，暂停依赖该答案的行动。
5. 首次安装后启动或提供命令，已有项目仅在用户需要打开界面时提供：
   ```sh
   python3 .workspace/app/workspace.py --project . --port 0
   ```
   返回实际打印的地址；不修改前端、不安装 Node，不把面板运行当成训练运行。
6. 信息足够且请求包含继续准备时衔接 build-evaluation；否则说明下一步和所需答案，不自动训练。

## 输出与完成

独立项目路径、目标与资源保存位置/修订、界面真实地址或启动方式、缺口与下一步；已存在工程及用户编辑保持不变。按基础 Skill 核验本次写入，不把工具包可打开等同于训练环境准备完成。

## 阻塞与恢复

缺 kit、格式不兼容、同名业务文件冲突分别报告；不删除已有文件。安装中断后先检查实际已安装内容，再用同一可信 kit 补缺；目标更新冲突则重读、合并并重新取哈希。
