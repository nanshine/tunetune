# 建立或接手研究

输入：用户目标、明确的项目目录、用户提供且已经从可信渠道核验的固定版本本地研究空间 kit（原型版 0.2.0）。不猜下载 URL、不从源码目录拼装安装、不修改全局 skills 或设置。缺少可信 kit 时说明阻塞及所需路径，不执行未知脚本；清单 SHA-256 不能认证发布者。

1. 检查目标目录、现有同名文件和用户已说明的情境、例子、期望结果、数据及执行限制。已有项目先读 `AGENTS.md`、目标、资源、当前评测、候选、最近 review 与未处理反馈；不要让用户重复填已明确的信息。
2. 使用 kit 根目录自带的一次性安装器（不是项目业务命令）：
   ```sh
   python3 /absolute/local/workspace-kit-0.2.0/install-workspace.py --kit /absolute/local/workspace-kit-0.2.0 --project /absolute/research/project --name '研究名称'
   ```
   路径必须换成用户提供的实际本地路径。安装器验证完整清单、路径与哈希，仅补缺失文件；同名业务内容不兼容或 app 版本冲突则停止处理，不删除旧文件、不绕过校验。本版不支持升级。`--name` 仅影响新建 project.json。
3. 读取安装后项目 `AGENTS.md` 的格式与写入契约，检查 `project.schema_version` 为 1 且在 `.workspace/manifest.json` 支持范围内。已有 AGENTS 会保留：若未含研究契约，先向用户说明差异，经明确同意后合并 kit 中 `template/AGENTS.md`，不要直接替换既有指令。
4. 把已知情境、期望结果、稳定 ID 的例子与聊天/文件来源写入 `goal.json`；资源调查只记录实际查到的条件、检查时间与限制。修改已有目标前保存旧 revision 到 history，再递增。关键写入前核对哈希、协调共享写入者。缺失信息保持待补充，必要时在 `feedback/requests/` 留绑定目标及哈希的问题；不编造指标或空实验。
5. 从项目目录启动或提供用户可执行的命令：
   ```sh
   python3 .workspace/app/workspace.py --project . --port 0
   ```
   若实际启动，返回进程打印的本地地址，不猜端口。运行无需 Node 或产品仓库；面板仅展示和保存反馈，runtime 不说明训练存活。不修改前端来“形成研究空间界面”。
6. 信息足够且请求包含继续准备时衔接 `build-evaluation`；否则给出下一步及阻塞问题，不自动训练。

输出：独立项目路径、已保存的目标/资源、研究空间服务启动方式或界面真实地址、缺失信息及下一步。只创建必要文件和目录；重初始化保持已有研究、反馈、产物、名称和展示配置。
