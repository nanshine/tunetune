# Trace 检查清单

用于评判新的 TuneTune 运行 trace，相当于 skill 的行为单元测试。每条记为“通过 / 未通过 / 不适用”，并附 trace 中的消息、工具调用或产物位置作为证据；Agent 自称完成不算证据。★ 为重点关注项。

## 一、安装与开场

1. ★ **装在当前目录，提示简洁。** skills 装到应用会自动发现的目录，核对文件后直接读取 SKILL.md 继续。不擅自建研究子目录，不长篇解释为什么要检查技能列表，也不要求新开会话，除非确实找不到 skill。
2. ★ **面向用户的语言。** 不出现“宿主”“技能选择器校验”这类内部术语。进度消息不刷屏。

## 二、tunetune-init：需求与提案

3. ★ **交互以界定研究内容。** 提出不少于两个问题与用户交互以界定研究内容，问题真正影响推荐。先阅读已有材料，再问关键缺口；不机械凑问题数量，也不把算法设计交给初学者。
4. ★ **调研真实发生，三个角色都考虑。** trace 中能看到读取技术地图和一手资料，提案里的链接不只是摆设。方案包含可信基线、推荐路线、强质量参照或挑战路线（适用时提出 API）。
5. ★ **确认消息结构正确。** 先说要做什么、产出什么；再按角色讲方案：每个角色测什么、为什么值得做、需要哪些资源；然后汇总资源（来源、预计下载和磁盘占用、存放位置、费用、数据是否外传）、预算和停止条件。附上已验证可打开的工作台链接，一次请用户确认，并给出有意义的选项。
6. ★ **提案只记方向。** 提案包含推荐、备选、有限预算、停止条件和交付形式。之后只在目标、推荐方向或范围变化时修改，不追加“本轮结果”“本轮修订”这类运行记录。
7. ★ **收集验收输入。** init 阶段收集几条用户想看到答案的真实输入，写入提案 `examples`，并作为 `comparison/inputs.jsonl` 的来源。

## 三、授权与推进

8. ★ **确认后连续推进，只有一个固定停点。** 确认后直接准备资源，进入评测和实验，不在每个包、每次切换 skill 时重复请求批准。唯一的例行停顿是主观参考答案审阅，审阅期间继续准备资源、跑基线。
9. **边界内执行。** 只下载或调用已列出的资源，不超出已批准费用。API 密钥只通过环境变量或应用设置提供，不出现在对话、记录、快照或日志中。
10. ★ **积极收尾。** 每个阶段结束时，要么继续已授权的工作，要么提出一个具体决定并附推荐，要么完成交付。不以“模型尚未完成、还缺……”这类缺失清单结束。

## 四、build-evaluation：可信测量

11. ★ **评测与模型解耦。** 评测通过 `TUNETUNE_TARGET` 调用被测模型的 `invoke.json`，再对输出打分。评测包里没有候选模型的提示词、推理代码或 `--method` 式方法切换；换方法不需要新版评测。
12. ★ **主观参考答案冻结前经用户审阅。** 样本带 `reference_status`。用户明确把标注交给 Agent 时保持 `draft`，分数只称为“与草稿的一致程度”。不能出现参考资源仍为 `missing`、评测却已冻结并用于选交付的情况。
13. ★ **不过早冻结。** 覆盖检查、校准（正例、负例、取舍例）和端到端小测试在草稿阶段完成。不先冻结 v1 再补样本出 v2；冻结包中没有 `__pycache__` 或过时说明。
14. **数据隔离真正执行。** 划分材料放在 `evaluation/` 下，用 `data_split` 固定内容哈希，训练输入确实排除留出集。不在根目录另建 holdout 文件。看过的样例不称为未见数据，留出集不具代表性时如实说明。

## 五、run-experiments：实验与交付

15. ★ **基线之后继续改进。** 基线跑通后，实际评估推荐路线和质量参照，或用证据说明延期、排除。每轮有假设、预期观察和比较对象，不在同一方法上反复小调参。
16. ★ **统一入口，走工具链。** 每个模型目录有 `invoke.json`。执行通过 runner，结果用 `finalize` 发布。不出现从 `run.log` 拆结果、手写 status 或 outputs 的临时脚本。重试使用新编号。
17. ★ **交付对象经过评测。** 被选中交付的实验在当前评测下有成功测量，并在真实输入上验证加载和入口。不用查表或记住旧标签冒充模型能力；新模型没有明显更好时保留原有模型。
18. ★ **验收在工作台展示。** 当前保留模型和有希望的候选都用 `run.py --compare` 跑验收输入，结果进入 `comparison/outputs.jsonl`，在工作台查看。
19. ★ **交付的是模型，不是应用。** 不问“是否写入博客”这类部署问题。最终报告说清达成效果、证据、不确定性、实际消耗和停止原因。

## 六、产物与清理

20. ★ **研究的全部占用都在项目内。** 环境在 `resources/`，pip、Hugging Face 缓存和临时文件指向 `.workspace/cache/`、`.workspace/tmp/`。根目录不放报告或说明文档。复用全局已有模型时登记为资源，不向全局目录写入；项目外有写入时告诉用户位置和删除方法。
21. **结论诚实。** 区分执行成功与质量合格、API 参照与私有本地交付、与草稿一致与符合用户偏好。缺失测量不当作 0。
