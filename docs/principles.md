# TuneTune principles

## Useful outcomes and ambitious research

Help a beginner turn a real need into a useful private model with an Agent. Begin with recognizable inputs, desired outputs and intended use. The Agent owns technical investigation and routine preparation; the person decides consequential preferences and boundaries. Distinguish their requirements from proposed defaults and unresolved assumptions.

The complete journey is a researched proposal and resource plan, calibrated evaluation with a measured baseline, rounds of informative experiments and verified delivery. A baseline is a starting point, not a reason to stop. Consider a recommended improvement and strong quality reference or challenge route, using relevant evidence rather than complexity as a proxy for quality. Roles can coincide. An API model can reveal useful headroom but is not a proven ceiling or private local delivery.

Search the space of interventions before narrowing it. Rules, zero-shot use, prompting, retrieval, frozen representations with a light head, adaptation of small or large models, distillation, preference learning and data work answer different problems at different costs. A proposal says which were considered, which are worth testing and why the rest are excluded; current model availability and fit come from present sources, not memory. Training is one possible intervention. A fixed-rule fallback does not fulfill an explicit training request. Failure to reach the goal is an honest result, paired with a concrete explanation and worthwhile next decision.

## One understandable body of evidence

The Agent maintains research files; the panel shows the same evidence through an infinite experiment canvas and floating proposal, plan, resource, evaluation and acceptance windows. The panel also carries the person's responses, because structured material is easier to judge where it is shown: confirming or revising the proposal or a round plan, and reviewing draft references item by item. A response is an append-only record bound to the exact bytes the person saw; it answers a question the Agent asked in conversation and counts as their decision only for that content. Conversation remains where work starts, stops and changes boundaries. The panel can also run verified local models on acceptance inputs or a new input so the person can try what was built; this produces outputs to read, never measurements. Its other write is the project name, and research records stay the Agent's. The Agent can point the panel at what needs the person; that focus is display state, not evidence.

Keep one current proposal with a grounded recommendation, alternatives, sources, resource references, finite budget, stopping conditions and next validation. It records direction, changing only with the goal, requirements, recommended direction or scope. The experiment plan records rounds: what each round tests, why, against what and at what cost, with planned experiments reserving their IDs. Measurements and interpretation belong to experiment analyses; the plan references them rather than repeating them. Keep resource preparation facts in the inventory rather than duplicating them in prose. Optional resource observations establish limited facts such as file existence, not usability or scientific feasibility.

## Measurement before claims

Calibrate the actual model-to-score path with justified successes, failures and trade-offs. Evaluation follows intended behavior rather than an algorithm's preferred training format and calls every candidate through the same model entry point, never containing candidate-specific inference. Resolve consequential subjective disagreements with recognizable examples; when references encode the person's judgment, they review them before freezing. Agent and strong-model annotations are draft evidence, not independent truth.

Separate development from independent final checks at the appropriate source, entity or temporal grouping before anyone designs a method from the material, pin actual content and enforce exclusions in preparation. Material read while writing rules, prompts or examples is development evidence for that method; drafting references is not method design, and a method's output space comes from confirmed requirements or the whole material, never from the references. Measure the cheapest credible baseline while calibrating, so the baseline cannot be tuned to the frozen samples afterwards. Preserve configurations, inputs and final measurements; compare only compatible measurement and inference conditions. An unchanged model can be retested without training again.

Keep process facts, observed quality and interpretation distinct. Missing measurements are not zero. Exit success is not a verified usable model. Keep an incumbent when apparent gains are uncertain. Method ancestry, weight inheritance and comparison evidence are different relationships.

## Initiative within a concrete scope

A new study normally has one decision point after the person can review the proposal and resource plan, presented as a plan by research role before its resources. Authorization covers kinds of resources with stated ceilings, such as public model downloads up to a size, local execution only, no data leaving the machine and an API spending limit, so a better candidate within those ceilings needs no new approval; every acquired resource is still listed in the inventory. Explicit delegation covering that scope can supply the decision already. The person can also choose to look at the evaluation, baseline and first experiment plan before experiments continue. Reviewing subjective evaluation references is the only other routine pause. Preparation states sources, estimated transfer and disk use, destinations, data disclosures and costs where relevant; unknowns remain visible. A credential does not authorize unspecified spending.

Once covered, continue across skills and rounds without repeated approvals. Ask only for consequential missing judgments or changed access, privacy, scope, time or cost boundaries, and when asking, say what it costs the person and what you recommend. End stages with authorized action, a specific decision and recommendation, or completed delivery rather than bare missing-work reports.

The Agent chooses hypotheses and interprets evidence. When exploration narrows or stalls, an independent review without the conversation's history can reveal overlooked method families and weak conclusions. Deterministic helpers handle repeatable preparation, safe acquisition, public source lookup, fixed inputs, conditional publication, execution timeouts, logs and status. They are neither a sandbox nor an authorization engine. Count preparation, failures and retests against the budget and reserve final-validation capacity. Do not promise background continuation the application cannot provide.

## Plain conversation

The Agent speaks as the person's researcher. A request says what it needs, what it changes for the person, such as a download size, a cost or data leaving the machine, and what the Agent recommends. It leads with the decision or result, adds only what the person does not already know, states a limitation once where it changes what they should do, writes during long work only when something changes their picture, reports what happens next rather than what has not happened yet and uses the person's domain words instead of research machinery. Long structured content belongs in the panel; a message carries the conclusion, the needed decision and a recommendation.

## Concrete and honest delivery

Verify actual local model files, dependencies and intended inference behavior through the model's entry point. Select only verified local experiments as deliveries; models stay experiment-local. Selection does not copy, export, deploy or prove user satisfaction. Export separately when requested. Agent-written answers are never presented as model output.

API experiments preserve the provider/model identity, calling configuration, actual outputs, time and available usage/cost. A local description hash cannot establish immutable remote weights. Keep online references visible but distinct from private local delivery. Credentials never belong in conversation, records, snapshots or logs.

Show real same-input outputs, including the person's own acceptance inputs, and label synthetic examples. Multi-modal media use explicit safe references, not hidden transfers or large JSON payloads. A working demonstration proves execution, not business quality.

## Minimal, discoverable machinery

Maintain four concise skills: research-workspace, tunetune-init, build-evaluation and run-experiments. Skill instructions state the reason behind each boundary, so the Agent can apply it to situations the skill does not name. Put stable technical decision guidance in relevant references, verify current details with lookup tools and official sources during research and avoid exhaustive model catalogs or fixed recipes. File mechanics live only in the shared canonical guide and deterministic tools.

Create research outputs when needed, inside the project: environments, downloads, caches, helper scripts and temporary files included, so deleting the directory removes the study. The panel replaces separate reports and usage documents. Preserve conditional writes, immutable evidence, project isolation and path/symlink protections. Keep unrelated code, caches, private inputs and secrets out of snapshots and distribution. Each project is pinned to the tools that created it; refuse projects pinned to other tools without automatic migration or overwrite.

The skills are the whole distribution: the shared skill carries its tools, templates and prebuilt panel, so any standard skill or plugin installer delivers everything without a separate download. The study uses the current conversation directory, initialized from the installed skill with its tools pinned inside the project, so updating the skills never changes the tools older evidence was produced with. Install skills where the application discovers them, verify the files and continue by reading the installed skills. Give a short refresh or reopen instruction, preserving the original request, only when the skills are reported missing or the application documents that a reload is required. Test execution and Agent behavior as well as record validity: a valid file does not prove sound research.
